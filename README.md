# AquaPath

تطبيق لتتبّع شاحنات توزيع المياه في قطاع غزة في الوقت الفعلي.

الفكرة بدأت من مشكلة واقعية: في غزة، توزيع المياه بصير عن طريق شاحنات، والناس ما بتعرف إمتى الشاحنة رح توصل منطقتها ولا وين هي هلأ. عملت AquaPath عشان يربط الأطراف الثلاثة — الأهالي، السواقة، والمؤسسات اللي بتدير التوزيع — بمكان واحد.

---

## المشكلة اللي بيحلها

قبل التطبيق، العملية كانت شغل ورقي ومكالمات. الأهل ما بيعرفوا موعد وصول المياه، والمؤسسة ما عندها صورة حيّة عن أسطول شاحناتها ولا عن المناطق الأكثر حاجة. AquaPath بيعطي:

- **للمستفيد (Resident):** خريطة حيّة بمواقع الشاحنات، وقت وصول متوقّع (ETA)، وإشعارات لما الشاحنة تقرب من منطقته.
- **للسائق (Driver):** إدارة رحلات التوزيع، بثّ موقعه الحي، وتسجيل كميات المياه الموزّعة.
- **للمؤسسة (Organization):** لوحة تحكم لإدارة السواقة والأسر والمناطق والشاحنات والجداول، مع مراقبة حيّة وتقارير.

كل نوع مستخدم بيدخل على واجهته الخاصة، والبيانات بتتدفّق بينهم بشكل لحظي.

---

## البنية المعمارية (Architecture)

بنيت المشروع على **Clean Architecture** بنمط **Feature-First**. كل ميزة (feature) مستقلّة بحالها وبتحتوي طبقاتها الثلاث:

```
lib/
├── core/        # الأدوات المشتركة: router, errors, theme, logging, security
├── features/    # كل ميزة فيها data / domain / presentation
└── shared/      # models و services و widgets مشتركة بين الميزات
```

السبب اللي خلّاني أختار Clean Architecture إنه المشروع فيه 3 أنواع مستخدمين وكل واحد إله منطقه الخاص — الفصل بين الطبقات خلّى كل جزء قابل للاختبار والتعديل بدون ما يكسر غيره.

**تدفّق البيانات** بيمشي هيك:

```
UI (Widget)
  → Riverpod Notifier / Provider
    → Repository (domain interface)
      → Firebase Source / Local Source (Hive)
        ↔ Firestore / SecureStorage / Hive
  ← Either<Failure, T>   # كل عملية بترجع يا نجاح يا فشل واضح
```

استخدمت `Either<Failure, T>` عشان أتعامل مع الأخطاء بشكل صريح — بدل ما ألاقي نفسي بـ try/catch مبعثرة، كل عملية بترجع نتيجة واضحة والـ UI بيتعامل معها بـ `fold()`.

## التقنيات (Tech Stack)

| الطبقة | التقنية |
|--------|---------|
| Framework | Flutter (mobile) |
| State Management | Riverpod v2 |
| Dependency Injection | GetIt |
| Backend | Firebase (Firestore, Auth, Cloud Functions, FCM) |
| Routing | go_router |
| Local Storage | Hive + SecureStorage |
| Maps | Google Maps |
| Functional errors | dartz (`Either`) |

استخدمت **Riverpod مع GetIt** مع بعض عن قصد: Riverpod لحالة الواجهة (streams و state)، و GetIt لحقن الاعتماديات (repositories و services). مش خلط عشوائي — كل واحد بمكانه.

## القرارات التقنية المهمة

في كم قرار أخذتهم بالمشروع وبحب أوضّحهم لأنهم شكّلوا طريقة عمله:

**1. الأدوار عبر Custom Claims مش عبر Firestore**

دور المستخدم (resident / driver / organization) مخزّن كـ **Firebase Auth custom claim**، بينزرع من **Cloud Function** بعد التسجيل — مش كحقل بقاعدة البيانات. السبب: أي حقل بالـ Firestore المستخدم ممكن يعدّله، بس الـ claim بينزرع من السيرفر بس. قرارات الصلاحية كلها بتعتمد عليه، والـ Firestore Security Rules بتتحقّق منه بكل عملية.

**2. الوضع الأوفلاين (Offline-first)**

بيئة غزة الإنترنت فيها متقطّع، فكان لازم التطبيق يشتغل حتى بدون اتصال. عملت `OfflineWriteQueueService` بيخزّن العمليات محليًا لما ما يكون في نت، وبيزامنها لما يرجع الاتصال. والبيانات المقروءة بتتخزّن بالـ Hive عشان تظهر فورًا.

**3. Firestore Security Rules محكمة**

بما إنه المشروع فيه بيانات حسّاسة عن الأسر (وجود كبار سن، مرضى، أطفال)، القواعد مكتوبة بحيث كل مستخدم يقرأ بياناته هو بس، والمؤسسة وحدها إلها وصول كامل. القواعد متتبّعة مع الكود بملف `firestore.rules` مش مكتوبة يدويًا بالـ Console.

**4. الإشعارات (FCM) بمواضيع عربية**

الإشعارات بتوصل حسب المنطقة عن طريق FCM Topics. أسماء المناطق عربية، والـ FCM ما بيقبل أحرف عربية بأسماء المواضيع، فعملت encoding خاص بيحوّل اسم المنطقة لصيغة مقبولة ويطابقها مع الـ Cloud Function.

**5. حساب المؤسسة بينشأ من الأدمن**

ما في تسجيل عام للمؤسسات — أول حساب مؤسسة بينزرع يدويًا عبر Admin SDK، وأي حساب بعده بتنشئه مؤسسة قائمة عبر Cloud Function. هذا مقصود عشان ما يقدر أي حدا يسجّل نفسه كمؤسسة ويوصل لبيانات الأسر.

## أهم الميزات

- تتبّع حيّ للشاحنات على الخريطة مع ETA محسوب حسب المسافة وعامل الازدحام.
- بثّ موقع السائق عبر foreground service مع كشف نقاط التوقّف.
- تسجيل كميات التوزيع مع validation على مستوى السيرفر (حد أقصى منطقي، ممنوع التلاعب).
- إشعارات لحظية حسب المنطقة.
- تقارير قابلة للتصدير بصيغ CSV و PDF و Excel، بتنشارك مباشرة بدون تنزيل على الجهاز.
- إعادة تعيين كلمة المرور، وvalidation كامل للإيميل وكلمة المرور.
- دعم كامل للعربية و RTL.

## التشغيل محليًا

```bash
# تثبيت الاعتماديات
flutter pub get

# التشغيل
flutter run

# بناء نسخة release
flutter build apk --release
```

المشروع بيحتاج ملف `google-services.json` خاص بمشروع Firebase، وربط مفاتيح Google Maps المقيّدة.

لنشر قواعد الأمان والفهارس:

```bash
firebase deploy --only firestore:rules
firebase deploy --only firestore:indexes
```
